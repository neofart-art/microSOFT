АНАЛИЗ СЕТЕВЫХ ПАПОК — 1.0

ЗАПУСК
1. Нужна Windows 10/11 и установленный Python 3.10 или новее с Tcl/Tk
   (обычный установщик Python). Сторонние библиотеки не нужны.
2. Распакуйте архив в локальную папку. Запустите Start.bat.
3. Введите UNC-путь, например \\fileserver\departments, или Z:\.
   Можно выбрать папку через «Обзор».
4. При необходимости включите получение владельцев. Нажмите «Сканировать».
5. Нажмите заголовок столбца для сортировки. Сохраните CSV на локальный диск
   ВНЕ сканируемой папки. Отчёт открывается в Excel, разделитель — точка с запятой.
   Рядом создаётся отдельный CSV с ошибками и пропущенными ссылками.

ЧТО ПОКАЗЫВАЕТ
• Каждая обнаруженная папка, включая корневую; размеры всех вложенных файлов.
• Логический размер в байтах и ГиБ (1 ГиБ = 1 073 741 824 байта).
• Количество файлов и вложенных папок.
• Наиболее поздняя дата обращения среди доступных файлов во всём поддереве.
• Наиболее поздняя дата изменения файла и его путь.
• По запросу: текущий владелец каждой папки и текущий владелец самого недавно
  изменённого файла во всём поддереве. Это НЕ автор и НЕ последний загрузивший.
• Статус полноты, количество ошибок и пропусков в поддереве, дата отчёта.

В окне отображаются до 10 000 самых больших папок; CSV содержит все папки.
При остановке можно экспортировать частичный результат — он явно помечен.
Остановка ожидает завершения текущего системного запроса: при зависшем SMB
ответе она может занять время. Длинные пути зависят от поддержки Windows/Python.

КАК ЧИТАТЬ РЕЗУЛЬТАТ
Размер родителя уже включает дочерние папки: суммировать все строки нельзя.
Сжатие, дедупликация, sparse-файлы, альтернативные потоки NTFS и физически
занятое место не учитываются. Жёсткие ссылки считаются по каждому имени.
Символические ссылки, junction и другие reparse points пропускаются,
чтобы избежать циклов, перехода в другие ресурсы и загрузки облачных файлов.
Недоступные и исчезнувшие во время обхода объекты записываются в журнал;
размеры таких поддеревьев неполные. Пустые даты не означают «никогда не читали».
Читаются только метаданные, содержимое файлов не открывается. Сервер всё же
может учитывать сам обход как обращение. Никакие ACL и настройки не меняются.
Сканирование не является атомарным снимком: данные могут меняться во время обхода.

ОГРАНИЧЕНИЯ ДАТ И АВТОРСТВА
Дата обращения берётся из файловой системы. Она может быть отключена,
обновляться с задержкой или отражать антивирус/резервное копирование, а не
действия человека. Она не доказывает, что папка не используется.
Владелец ACL может отличаться от создателя, меняться администратором или
отображаться как общая учётная запись NAS. Нет доступа — указан код ошибки.
Дата изменения не равна дате загрузки: при копировании время может сохраниться.
При одинаковых датах показывается один из файлов с максимальной датой.
Точно узнать, кто создал папку или последним записал данные, задним числом
можно только при наличии подходящих сохранённых журналов аудита сервера.
Для дальнейшего учёта авторов потребуется отдельный сбор событий записи:
Windows Server — файловый аудит, Linux/Samba/NAS — аудит средствами сервера.

ПРАВА И НАГРУЗКА
Запускайте под обычной учётной записью с доступом к ресурсу. Для чтения
владельцев могут потребоваться дополнительные права. Запуск от администратора
может скрыть подключённые диски — используйте UNC-путь. Программа не запрашивает
и не сохраняет пароли. На больших ресурсах первый проход может быть длительным;
получение владельцев добавляет сетевые запросы. Список папок и ошибок хранится
в памяти. Для миллионов папок потребуется отдельная версия с базой данных.

КОМАНДНАЯ СТРОКА
py -3 audit.py --path "\\fileserver\departments" --csv "C:\Reports\folders.csv" --owners
Папка для CSV должна существовать. Код выхода 2 означает ошибки обхода.
Без --owners владельцы не запрашиваются. Без --path открывается окно.

ПРОВЕРКА ВЕРСИИ
Логика обхода, агрегация размеров/дат, пропуски ссылок, ошибки, отмена и CSV
проверены на тестовых данных Linux. GUI и Windows API владельцев требуют
проверки на реальном Windows-ПК и вашем сетевом сервере.
