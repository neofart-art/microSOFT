# RDP Shadow Manager

Небольшая portable-утилита на C# / WinForms и .NET 10 LTS для Windows 10 (22H2) / 11 x64. Использует Windows WTS API и штатный mstsc.exe. Установщик, Python и отдельно установленный .NET не нужны. Другие файлы репозитория не изменяются.

## Репозиторий разработки

Основной репозиторий разработки: [GitHub — microSOFT](https://github.com/neofart-art/microSOFT). Рабочая ветка: `codex/rdp-shadow-manager`, каталог приложения: `RdpShadowManager`.

```text
git clone --branch codex/rdp-shadow-manager https://github.com/neofart-art/microSOFT.git
cd microSOFT
```

Для разработки fetch/push и Pull Request выполняются в GitHub (`origin`), portable-сборка поддерживается через GitHub Actions. Внутренний `http://git.fors.technology/techadmin/MiniSoft.git` сохранён как remote `fors` только для копии: пользователь обновляет её самостоятельно со своего Windows-ПК. Среда разработки не обращается к `fors` и не отправляет туда изменения. Подробности и команды ручного обновления: [MIGRATION.md](MIGRATION.md).

## Скачать и запустить

Откройте вкладку **Actions** репозитория → **RDP Shadow Manager Windows x64** → успешный запуск для нужного коммита → **Artifacts** → **RdpShadowManager-win-x64**. Для скачивания артефактов нужен вход в GitHub. Срок хранения — 30 дней; при истечении запустите workflow заново через Run workflow (после появления workflow в основной ветке) либо выполните локальную сборку.

Распакуйте скачанный архив GitHub, затем вложенный `RdpShadowManager-win-x64.zip` в отдельную папку. Запустите `RdpShadowManager.exe`. Если Windows показывает предупреждение для неподписанного файла, проверьте источник и коммит сборки согласно правилам вашей организации. Приложение не подписано цифровой подписью.

Введите имя ПК, FQDN или IP (IPv4/IPv6 без квадратных скобок), нажмите «Получить сеансы», выберите активного пользователя и нажмите «Подключиться». По умолчанию запрашивается согласие пользователя. Режим без запроса добавляет `/noconsentprompt`. Окно остаётся открытым. Неактивные сеансы видны, но подключение заблокировано. Тайм-аут запроса настраивается от 3 до 120 секунд, по умолчанию 15.

## Права и политики

Программа использует текущую учётную запись, не запрашивает и не хранит пароли. Требуются права получения сведений о сеансах и управления выбранным сеансом на целевом ПК; обычно это разрешённая удалённая административная учётная запись. Удалённая система должна поддерживать RDP Shadow; редакция Windows и ограничения сеансов имеют значение. На целевом ПК должны быть доступны службы RDS/RPC и соответствующие разрешённые правила брандмауэра.

Политика «Задать правила удалённого управления для сеансов пользователей служб удалённых рабочих столов» должна разрешать нужный режим управления и согласия. `/noconsentprompt` не обходит права или политику. Подключение Shadow не меняет реестр, GPO, RDP, службы и брандмауэр. Отдельное обслуживание AutoDiscover изменяет только перечисленные ниже значения Outlook после явного подтверждения. В отдельной группе «Администрирование» показан текущий уровень прав. Кнопка перезапуска с UAC недоступна при повышенных правах. После перезапуска сохраняются введённый компьютер и режим согласия, а список сеансов запрашивается заново: старый выбор не переносится. Отмена UAC оставляет исходное окно открытым. Повышение даёт только локальные права и само по себе не даёт удалённых прав. Работайте только с компьютерами и сеансами, которыми вам разрешено управлять.

На Windows установите .NET 10 SDK и выполните из PowerShell:

```powershell

```

Скрипт запускает автоматические проверки и создаёт self-contained win-x64 ZIP в `RdpShadowManager/artifacts`. Workflow выполняет тот же скрипт и дополнительно проверяет запуск опубликованного WTS-процесса с localhost. Без Windows можно выполнить только независимые проверки логики:

## Диагностика

Раскройте «Диагностика» и скопируйте текст. Журнал в памяти содержит время с часовым поясом, компьютер, операцию, код и текст ошибки; на диск автоматически не записывается. Он может содержать имя компьютера и сведения о сеансах.

- Код 5: отказ в доступе — проверьте удалённые права и ограничения учётной записи.
- Коды 53/1722: недоступен компьютер, RPC или служба — проверьте имя, сеть, службы и правила брандмауэра. Это не обязательно ошибка DNS.
- Коды 11001/12007: ошибка разрешения имени — проверьте DNS или попробуйте IP.
- Тайм-аут: вспомогательный процесс завершается; следующий запрос не создаётся до завершения предыдущего. Ping не используется.
- Нет пользователей: служебные записи и сеанс 0 исключены; недоступные поля отражаются в диагностике. При недоступном имени пользователя запись исключается, поскольку подключение невозможно безопасно адресовать пользователю.
- Сеанс изменился: обновите список и выберите заново. До запуска перепроверяются ID, пользователь, домен и активное состояние. Между проверкой и mstsc остаётся неизбежная гонка внешних процессов.
- «Клиент подключения запущен» подтверждает только запуск mstsc. Ошибки RDP отображаются в его собственном окне.

## Проверки и ограничения

Автотесты проверяют адреса и попытки добавления ключей, оба набора аргументов mstsc, некорректные ID, смену пользователя/домена/ID и отключение сеанса. WTS-вызовы изолированы в одном вспомогательном процессе с отменой, тайм-аутом и освобождением памяти/дескрипторов. При изменении адреса старый список очищается, ответ отменённого запроса игнорируется.

Исходная среда разработки — Linux без .NET SDK и с недоступным сетевым прокси. Локальная компиляция и реальные RDP-подключения в ней не выполнялись. Результат компиляции, автоматических тестов и smoke-проверки смотрите в конкретном запуске Actions. Полный список обязательных ручных проверок — в [MANUAL-TESTS.md](MANUAL-TESTS.md); успешный workflow не подтверждает их прохождение.

## Обслуживание: предоставленный профиль AutoDiscover

Кнопка «Исправить Outlook AutoDiscover» открывает диалог **«Применение предоставленного профиля AutoDiscover»**. Это конкретный профиль из [оригинального BAT](https://github.com/neofart-art/microSOFT/blob/codex/rdp-shadow-manager/RdpShadowManager/Reference/Outlook%20repeirNE.bat), а не универсальное решение проблем Outlook. BAT сохранён байт в байт для справки, приложение его не запускает. Если запускать оригинал вручную, он требует прав администратора, использует HKCU запускающего пользователя, содержит pause и общий taskkill; для обслуживания выбранного пользователя используйте встроенный помощник.

### Удалённый механизм и права

RDP Shadow управляет экраном; обслуживание выполняется отдельно через **Windows PowerShell 5.1 / WinRM (PowerShell Remoting)** с текущей учётной записью. PsExec и дополнительные загрузки не нужны. Требуются административный токен на целевом компьютере, доступ к PowerShell endpoint, WinRM listener и разрешённое сетевое правило (обычно TCP 5985). Для доменного имени используется штатная Windows-аутентификация. Работа по IP/в рабочей группе зависит от заранее настроенной администратором аутентификации и TrustedHosts; программа их не меняет, не запрашивает пароли и не включает WinRM. При недоступном механизме выводится его ошибка; локального запасного запуска нет.

Локальный UAC сам по себе не даёт удалённых прав. Помощник требует повышенные **удалённые** права. Он проверяет контекст WinRM, запрещает обслуживание компьютера с локальным MachineGuid, повторно сверяет пользователя/домен/активность сеанса через WTS и определяет SID на целевом ПК. HKCU администратора/SYSTEM не используется: пользовательские записи идут только в загруженный `HKEY_USERS\<SID>`. При недоступном SID или профиле операция останавливается. Перед изменениями и перед каждой записью цель перепроверяется. Сеанс может завершиться между отдельными системными вызовами; записи всегда остаются привязаны к первоначальному SID.

### Применение

Выберите активный сеанс и откройте обслуживание. После удалённой проверки диалог показывает компьютер, DOMAIN\пользователя, ID и SID. Обнаружение Outlook проверяет InstallRoot вместе с OUTLOOK.EXE, а ClickToRun — установленный продукт и фактическую версию классического OUTLOOK.EXE. Ветки 15.0/16.0 выбираются автоматически, ручного выбора нет. Office 2019 с версией 16.0.19127.20860 соответствует ветке 16.0. Если независимо подтверждены обе версии, обрабатываются обе. Неизвестная, неподдерживаемая или противоречивая версия останавливает применение без изменения реестра и без закрытия Outlook. Одного ключа ClickToRun или маркетингового названия Office недостаточно; установка повторно проверяется перед применением. При восстановлении версии берутся из выбранной копии.

В обычной ветке `Software\Microsoft\Office\<версия>\Outlook\AutoDiscover` задаётся `excludeexplicito365endpoint=1` (DWORD). В `Software\Policies\Microsoft\Office\<версия>\Outlook\AutoDiscover` задаются DWORD=1: `disableautodiscoverv2service`, `excludeexplicito365endpoint`, `excludehttpredirect`, `excludehttpsautodiscoverdomain`, `excludehttpsrootdomain`, `excludelastknowngoodurl`, `excludescplookup`, `excludesrvrecord`.

Обе ветки обрабатываются в HKU выбранного SID и HKLM, в явных Registry32/Registry64. В отличие от неполной WOW6432Node-ветки исходного BAT, Policies также обрабатывается в обоих представлениях. Windows может разделять одни физические значения между представлениями: уже совпадающие значения учитываются как пропущенные. **HKLM относится ко всему удалённому компьютеру и может повлиять на других пользователей** — предупреждение показано до «Выполнить».

Флажок закрытия Outlook по умолчанию выключен. Если включён, требуется отдельное подтверждение потери несохранённых данных. Завершение выполняется по удерживаемому дескриптору процесса после проверки имени OUTLOOK.EXE, SID токена и ID сеанса, а не глобальным taskkill. Ошибки закрытия останавливают записи и попадают в отчёт. Outlook может быть запущен пользователем повторно во время операции.

### Резервная копия и точное восстановление

До первой записи создаётся полный JSON-снимок всех затрагиваемых значений на **удалённом** ПК: `%ProgramData%\RdpShadowManager\Backups\<ID операции>.json`. Снимок содержит компьютер/MachineGuid, SID, пользователя, ID сеанса, время, версии и для каждого значения путь, представление, имя, наличие, исходный тип и данные без раскрытия ExpandString. Сохраняются String/ExpandString/MultiString/DWORD/QWORD/Binary/None. Каталог копий доступен только SYSTEM и администраторам; небезопасные ссылки и посторонние ACL блокируют использование. Файлы журнала заменяются атомарно, данные сбрасываются на диск. Без сохранённого снимка записи не начинаются.

«Восстановить предыдущие настройки» предлагает копии только данного компьютера и SID. До запуска проверяются конфликты, затем проверка повторяется удалённо и перед каждой записью. Если текущее значение отличается и от исходного, и от записанного программой, восстановление останавливается; конфликт с типами/данными виден в отчёте. Принудительного перезаписывания конфликтов нет. Возвращаются исходные значения и типы; удаляются только значения, отсутствовавшие до применения. Целые ключи не удаляются. Уже восстановленные значения защищены от повторного затирания последующих правок.

Отдельная удалённая блокировка не допускает одновременного обслуживания одним помощником. Это не транзакция реестра: при ошибке/отключении сети возможен частичный результат, сохранённый снимок и журнал намерения записи позволяют восстановление. Обрабатываются только записи, которые помощник пытался менять; пропущенные и ещё не затронутые записи остаются нетронутыми. Для нормальной работы интерфейс блокирует повторный запуск и изменение цели, но остаётся отзывчивым. Закрытие окна ожидает завершения обслуживания. Лимит помощника — 100 секунд между операциями, транспорта — 150 секунд. При тайм-ауте нельзя считать операцию успешной: удалённый вызов может ещё завершаться. Повторное обслуживание в текущем окне блокируется; проверьте удалённую копию и завершение помощника перед перезапуском программы.

Полный диагностический отчёт включает цель, версии, изменённые значения, счётчики успешных/пропущенных/ошибочных операций, ошибки, путь копии и ID операции; автоматически он не открывается. Итоговое окно содержит понятное резюме без команд и JSON, а при ошибке или частичном выполнении — причину и счётчики. Успех показывается только после завершения помощника с кодом 0 и проверки записанных значений. Ненулевой код возвращается при нехватке прав, неизвестных параметрах, конфликтах и других ошибках. Отчёт можно скопировать. Автотесты Windows проверяют запрет прямого локального запуска, компиляцию нативного помощника, соответствие плана BAT, типы и точное восстановление на временном тестовом ключе, а не на настройках Outlook.

## Питание удалённого компьютера

Отдельная группа под картинкой содержит «Перезагрузить компьютер», «Выключить компьютер» и «Отменить запланированное действие». Выбор пользовательского сеанса не требуется: **питание затрагивает весь целевой компьютер и всех его пользователей**.

Перед каждой операцией открывается подтверждение с именем и IP цели. Для перезагрузки/выключения задаются задержка (по умолчанию 60 секунд, диапазон 0–315360000), комментарий (до 512 символов) и «Принудительно закрыть приложения» (по умолчанию выключен). Предупреждение о потере несохранённых данных показано рядом. Запрос отправляется только кнопкой «Выполнить»; Enter не запускает его автоматически. «Отмена» закрывает диалог без отправки запроса.

Используется [InitiateSystemShutdownExW](https://learn.microsoft.com/en-us/windows/win32/api/winreg/nf-winreg-initiatesystemshutdownexw) с отдельным BOOL `bForceAppsClosed`, точно соответствующим флажку: положительная задержка его не включает. `InitiateShutdownW` намеренно не выбран: для удалённого запроса он требует `SHUTDOWN_FORCE_SELF`. Командная строка shutdown.exe, WinRM и локальное выключение как запасной вариант не используются. При выключенном флажке несохранённые документы могут задержать или заблокировать завершение работы; принятие запроса не гарантирует выполнение.

Цель фиксируется при открытии диалога вместе с разрешённым IP, и Windows API получает явное `\\<IP>` (для IPv6 — UNC ipv6-literal.net). Изменение DNS или поля компьютера не перенаправляет подтверждённый запрос. Для исключения случайного локального действия запрещены пустые имена, localhost, имя текущего ПК, loopback/unspecified/служебные адреса и адреса локальных интерфейсов, в том числе IPv4-mapped IPv6. Если DNS вернул несколько адресов и хотя бы один локальный, запрос блокируется целиком. Если IP не определён, питание не отправляется: укажите проверенный удалённый IPv4 или глобальный IPv6. IPv6 с идентификатором зоны не поддерживается. Проверка локальных адресов повторяется в процессе-помощнике и перед нативным API; нулевой или пустой указатель имени не передаётся.

Запрос выполняется вне UI в отдельном процессе. Во время подготовки/подтверждения/отправки повторное нажатие и другие операции блокируются, окно остаётся отзывчивым. При зависшем RPC помощник завершается через 20 секунд. Это **не отменяет** уже доставленный запрос: при отсутствии ответа показывается неизвестный результат, автоматического повтора нет. При необходимости явно запросите отмену на той же цели.

Отмена использует [AbortSystemShutdownW](https://learn.microsoft.com/en-us/windows/win32/api/winreg/nf-winreg-abortsystemshutdownw) и тоже требует подтверждения фиксированной цели. Она может отменить ещё отменяемое действие, запланированное другим администратором. При нулевой задержке отмена через этот API невозможна; после окончания отсчёта отмена также может быть недоступна. Успешная отправка отображается как «Запрос на перезагрузку/выключение принят» с целью и задержкой; завершение питания не заявляется.

### Права и ошибки питания

Текущей учётной записи требуется право **«Принудительное завершение работы из удалённой системы»** (`SeRemoteShutdownPrivilege`) на целевом ПК, а также доступ к штатному механизму удалённого выключения/RPC. Локальный UAC сам по себе не выдаёт удалённое право. Программа не назначает права, не включает службы и не меняет политики/брандмауэр. Разрешённые сетевые правила и права настраиваются администратором отдельно.

В диагностике фиксируются операция, фиксированная цель/IP, время, задержка, принудительное закрытие, комментарий и системный результат. Коды 5/1314 — доступ/привилегии; 53/64/67/1231/1722 — сеть или RPC; 1115/1190 — уже начатое/запланированное завершение; 1116 — нет отменяемого действия. Ошибка не приводит к локальному запросу, автоматическому повтору или замене уже существующего плана.

Автотесты используют подменённый API: проверяют оба действия, задержки 0/60/120, оба значения force, отмену, сохранение кодов ошибок и запрет локальных/пустых целей. Windows smoke-проверка проверяет защиту помощника и диалог; реальный API питания в тестах не вызывается. Реальная перезагрузка, выключение, отмена, показ комментария пользователям и права проверяются **только на специально выделенной Windows-машине**. В текущей среде такой машины нет; эти сценарии не проверены.



## Сведения о выбранном ПК и результат AutoDiscover

Кнопка «Подключиться» имеет размер 400 × 46 логических пикселей, полужирный текст, зелёную рамку и отдельные состояния наведения, нажатия и клавиатурного фокуса. Недоступная кнопка серая.

Под картинкой показываются сведения **выбранного** ПК. После успешного получения сеансов запускается независимый асинхронный запрос через существующий PowerShell Remoting / WinRM. Он не задерживает таблицу или mstsc; кнопка ↻ обновляет только сведения. Лимит запроса — 30 секунд. При изменении адреса данные сразу очищаются, предыдущий запрос отменяется, запоздалые ответы игнорируются. Службы и агенты не устанавливаются и не включаются; права и WinRM должны быть настроены администратором заранее. Локального запасного источника нет.

Windows: CIM Win32_OperatingSystem.Caption и удалённый CurrentVersion (DisplayVersion/ReleaseId, CurrentBuildNumber, UBR). IP берётся с активного удалённого интерфейса; интерфейсы со шлюзом имеют приоритет. Все IP показаны непосредственно в поле «IP-адреса», каждый на отдельной строке. Если удалённые адреса недоступны, используется явно подписанный «IP по DNS»; это разрешение выбранного имени, а не подтверждение сетевой конфигурации ПК.

Office: ProductReleaseIds/VersionToReport/Platform Click-to-Run и MSI-записи Uninstall в обоих представлениях реестра. Каждый обнаруженный продукт показывается отдельно, с версией и разрядностью; технический ProductReleaseId сохраняется для точного определения лицензии. Win32_Product не используется. «Office не установлен» означает, что оба источника прочитаны успешно и продуктов не найдено. При ошибках отображаются известные сведения и «Не удалось определить». Необычные установки без регистрационных записей могут не обнаруживаться. Подробности ошибок сохраняются в диагностике и не блокируют RDP Shadow.

В «Обслуживании» под кнопкой показывается только краткий цветной итог: «Настройки применены», «Применены частично», «Не удалось применить» или «Результат не подтверждён». Компьютер, пользователь и время доступны в подсказке; подробности сохраняются в диагностике. Зелёный успех требует завершённого ответа, кода 0, совпадения операции/SID/компьютера и проверки записанных значений. При частичном выполнении итоговое окно объясняет, что изменено, что не выполнено и почему. При потере ответа успех не заявляется. Для восстановления используются отдельные тексты. PowerShell запускается скрыто с перенаправлением потоков, без консоли и показа команд. Во время записи не показываются ход операции и промежуточные уведомления, повторный запуск блокируется. По завершении появляется краткое итоговое окно, без автоматического открытия полного отчёта.

CI проверяет состояния сведений с подменённым транспортом (WinRM недоступен, отсутствие Office, несколько IP, DNS, смена цели во время загрузки). Проверка разметки 100/125/150/200% остаётся программной имитацией; реальные Windows DPI и удалённые Click-to-Run/MSI установки требуют проверки на выделенных ПК.


## История адресов компьютеров

Поле компьютера — редактируемый список с автодополнением по сохранённым адресам. При нажатии «Получить сеансы» корректное имя/IP добавляется в начало истории; доступность ПК не является условием сохранения. История содержит не более 30 адресов без повторов регистра. Выбор адреса только подставляет его в поле, очищает старые сеансы, сведения и результат обслуживания; сам по себе он не запускает подключение или удалённую команду.

Адреса сохраняются между запусками в `%LOCALAPPDATA%\RdpShadowManager\address-history.json` текущей Windows-учётной записи. EXE можно держать в папке без прав записи; дополнительные установки не нужны. Это отдельные пользовательские данные portable-приложения, а не файл рядом с EXE. Сохраняются только имена/IP, без паролей, доменов пользователей или сведений о сеансах. Для очистки истории закройте программу и удалите этот файл. Разные Windows-учётные записи имеют раздельную историю.

Запись выполняется через временный файл и атомарную замену. Ошибки чтения/записи и повреждённый JSON отражаются в диагностике и не блокируют получение сеансов или подключение. Некорректные записи игнорируются; слишком большой файл не загружается. При недоступном хранилище список продолжает работать в памяти.

Автотесты проверяют сохранение и повторное чтение, валидацию, предел 30 адресов, повторы, повреждённый/слишком большой файл и ошибку записи. Проверка опубликованного EXE дополнительно создаёт два окна с отдельным тестовым хранилищем: проверяет восстановление списка, автодополнение, сброс старой цели при выборе и отсутствие сброса при обновлении истории неизменившегося адреса. Реальные профили пользователей в этих тестах не изменяются.


Сведения о ПК представлены четырьмя копируемыми полями только для чтения: «Компьютер» и «IP-адреса» рядом, «Windows» и «Office» — на всю ширину блока. Поддерживаются выделение мышью и Ctrl+C, перенос строк и вертикальная прокрутка длинного значения без потери текста. Кнопка обновления сохранена. CI проверяет отдельное копирование полей, формирование веток 15.0/16.0 на фикстурах, запрет записи при неоднозначности, итог частичного выполнения и скрытые настройки запуска PowerShell. Реальные установки Outlook и отсутствие всплывающей консоли на интерактивном рабочем ПК требуют ручной проверки.
