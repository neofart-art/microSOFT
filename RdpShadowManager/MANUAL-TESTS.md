# Ручная проверка на Windows

Следующие сценарии в исходной Linux-среде **не проверены**. Выполнять на разрешённых тестовых компьютерах, фиксируя версию Windows, язык, масштаб и результат.

- Windows 10/11 x64: запуск распакованной сборки на машине без .NET и Python.
- Получение сеансов по имени, FQDN, IPv4 и IPv6; русская и английская Windows.
- Несколько пользователей, активные и отключённые сеансы; отсутствие пользователей и исключение служебных записей / ID 0.
- Оба режима mstsc: согласие по умолчанию; без согласия при разрешающей и запрещающей политике. Главное окно остаётся открытым.
- Отказ в доступе, неверное имя DNS, выключенный ПК, недоступный RPC, заблокированный ICMP при доступном WTS.
- Недоступность отдельного WTS-поля: доступные данные сохраняются, ошибка есть в диагностике.
- Смена адреса во время запроса: очистка списка, завершение worker, отсутствие старых результатов. Повторные нажатия не создают параллельных worker.
- Тайм-аут 3 секунды для недоступного ПК: окно отзывчиво, worker завершён, следующий запрос возможен. Закрытие окна во время запроса не оставляет worker.
- Завершение/отключение сеанса или переиспользование ID другим пользователем перед нажатием «Подключиться»: запуск блокируется, нужен новый выбор.
- Отсутствующий mstsc и отказ запуска: понятная ошибка, системные подробности в диагностике.
- UAC: отдельная группа и статус обычных/повышенных прав; кнопка отключена при повышенных правах. При подтверждении сохраняются адрес и оба варианта режима согласия, сеансы загружаются заново без старого выбора. При отмене сохраняется исходное окно. Проверить отдельно, что локальное повышение не заменяет удалённые права.
- Масштаб 100/125/150/200%, перенос между мониторами: видимость и доступность элементов; раскрытие и копирование диагностики, работа клавиатурой.

Автоматическая Windows smoke-проверка проверяет только локальный WTS-процесс, не удалённый Shadow и не GUI.

## Удалённое обслуживание AutoDiscover — не проверено на реальных ПК

- Администратор и пользователь с разными SID: меняется только HKU SID выбранного пользователя; HKCU администратора/SYSTEM и локальный ПК не изменяются.
- Несколько активных пользователей: явная цель в диалоге, проверка SID при переиспользовании ID, остановка при выгруженном профиле.
- WinRM выключен/недоступен, отказ endpoint или удалённых административных прав: нет локального fallback, ненулевой результат и подробный отчёт.
- Office MSI 15/16, ClickToRun с классическим Outlook и без него; неподдерживаемая версия 14.0 должна останавливать новое применение (восстановление прежних копий сохраняется); нет Outlook или версия неоднозначна — никакой записи, понятная причина без ручного выбора веток.
- Исходные значения разных типов, отсутствующие значения, обе ветки и представления: полный снимок до записи, точное восстановление, сохранение самих ключей.
- Изменение значения сторонним приложением до/после preview: конфликт показан, принудительного перезаписывания нет. Повторная правка после успешного восстановления также конфликтует.
- Ошибка/обрыв сети между записью и подтверждением: результат не объявлен успешным, копия и журнал пригодны для последующего восстановления.
- Отсутствие доступа к каталогу резервных копий или небезопасный ACL: записи не начинаются.
- Закрытие Outlook выключено по умолчанию; включение требует предупреждения. Завершается Outlook только с совпадающими SID и ID сеанса; другие пользователи и сеансы не затронуты. Ошибки завершения отражаются в отчёте.
- Двойное нажатие, параллельный клиент и закрытие окна во время обслуживания: нет параллельной записи, интерфейс отзывчив, результат и путь копии видны.

Автотесты используют только одноразовый ключ HKCU `Software\RdpShadowManager-Tests-<GUID>` на Windows-машине, где запускается скрипт проверки и удаляют его после проверки. Это тест механизма сохранения типов, а не запуск профиля AutoDiscover на локальном компьютере администратора.

## Картинка и иконка

- Реальный масштаб Windows 100/125/150/200% и переход между мониторами: полная картинка не искажается, не перекрывает кнопки и таблицу; её колонка добавлена к прежней ширине окна.
- Маленькая/большая иконки EXE в Проводнике, главного окна, Alt-Tab и панели задач; читаемость лица на 16/24/32 px.
- Перенести только portable EXE/README на чистую машину: JPG/ICO рядом не требуются.

Проверка `--ui-smoke <каталог>` выполняет программную симуляцию масштаба и сохраняет изображения разметки; реальные системные DPI и панель задач в интерактивном Windows-сеансе пока не проверены.

## Питание — только специально выделенный тестовый ПК, не проверено

- Убедиться, что цель не является рабочим компьютером администратора; подтвердить имя и IP перед каждой операцией.
- С обычной/разрешённой удалённой учётной записью проверить отказ 5/1314 и успешный запрос. Проверить недоступный RPC/компьютер.
- Перезагрузка и выключение с задержкой 60 секунд, видимость комментария всем пользователям; статус говорит только о принятом запросе.
- Несохранённый документ: force выключен — приложение не закрывается принудительно; force включён — предупреждение есть, на тестовых данных подтвердить поведение. Проверить с нулевой и положительной задержкой.
- Отмена в течение отсчёта; отсутствие действия для отмены (1116); уже запланированное действие (1115/1190); отсутствие автоматической замены или повтора.
- Изменение поля/результата DNS после открытия диалога не меняет адрес запроса. Пустое имя, localhost, local FQDN/alias/IP, IPv4-mapped loopback, смешанный DNS с локальным адресом блокируются.
- Закрыть диалог через «Отмена»/крестик: запроса нет. Двойное нажатие: один запрос. Интерфейс отзывчив во время RPC.
- Тайм-аут после возможной доставки: результат неизвестен, приложение не сообщает об отмене или завершении питания; явно отменить на зафиксированной цели при необходимости.
- Восстановить стенд после выключения вручную; убедиться, что на локальной машине питания не запрашивалось.

Автоматические проверки не вызывают InitiateSystemShutdownExW/AbortSystemShutdownW: проверка запросов выполняется только с подменённым адаптером. Это не подтверждает реальную работу удалённого питания.


## История адресов — ручные проверки

- Ввести несколько ПК/IP, нажать «Получить сеансы», закрыть приложение и открыть вновь: список и порядок последних адресов сохранены; ввод с автодополнением и выбор из списка работают.
- Выбор другого ПК очищает сеансы, сведения и уведомление обслуживания. До нового получения сеансов подключение недоступно; выбор не запускает mstsc/WinRM.
- Запуск EXE из папки без прав записи: история хранится в LocalAppData. Повышение UAC под той же учётной записью использует её историю; запуск под другой учётной записью — отдельный файл.
- Повреждённый файл или отсутствие доступа к LocalAppData: окно продолжает работать, ошибка в диагностике, получение сеансов не блокируется.
- Реальная смена Windows DPI 100–200%: раскрытие списка, автодополнение, клавиатурный выбор и зелёная рамка кнопки. Программный smoke-тест не заменяет проверку выпадающего окна при реальном DPI.


## Новая компоновка и автоматический профиль

- Windows 100/125/150/200%: кнопка 400 × 46 при 100%, зелёная рамка сохранена; в расширенной правой колонке доступны все поля и кнопки питания (при необходимости через прокрутку).
- Выделение и Ctrl+C отдельно для имени, единственного IPv4, Windows и длинного Office; каждое значение копируется полностью, редактирование запрещено.
- Outlook 2013 MSI/C2R → 15.0; Outlook 2016/2019/2021/Microsoft 365 с FileVersion 16.x → 16.0. Две достоверно установленные версии → обе. Неизвестный, новый Outlook без классического OUTLOOK.EXE, противоречивые сведения или отказ доступа → остановка без записи.
- Перезапуск/обновление Office между подтверждением и записью: несовпадение автоматически определённых версий блокирует операцию.
- Во время обслуживания нет консоли/окна PowerShell, индикатора прогресса, промежуточного текста или вывода команд. По завершении только краткий итог под кнопкой и окно резюме; частичное выполнение всегда с объяснением причины, подробности — в диагностике.
- Восстановление старых резервных копий доступно даже при невозможности определить текущую версию Outlook; конфликт не перезаписывается автоматически.


## stderr и единственный IPv4

- На тестовом удалённом ПК повторно применить профиль: изменено 0, уже соответствовало 36, ошибок 0, код 0, stderr содержит только progress/инициализацию. Итог «Настройки AutoDiscover уже актуальны. Изменения не требуются», зелёный, без модального предупреждения.
- Проверить progress + настоящий Error, отказ прав, конфликт и потерю подтверждения: они не маскируются как уже актуальное состояние. В диагностике есть исходный stderr и раздельные служебные/ошибочные записи.
- ПК с LAN 172.31.1.11, VPN и IPv6: при активном подключении mstsc через LAN поле содержит только «IPv4: 172.31.1.11». Ctrl+C копирует это значение, список адресов и IPv6 не показываются.
- До подключения/при невозможности определить endpoint используется основной удалённый IPv4; источник в подсказке. Если данные недоступны, адрес не угадывается по первому DNS-ответу.
- Переключить ПК во время опроса соединения: старый IP не появляется. Проверить завершение/reuse mstsc, RD Gateway и работу при запрете чтения таблицы TCP — должен оставаться безопасный fallback с корректным источником.

CI проверяет классификацию stderr и приоритет IPv4 на синтетических данных; настоящий RDP с несколькими сетевыми интерфейсами требует ручной проверки.
