# Разработка в GitHub и внутренняя копия

## Текущий порядок работы

- Основной репозиторий: [neofart-art/microSOFT](https://github.com/neofart-art/microSOFT).
- Рабочая ветка: `codex/rdp-shadow-manager`.
- Программа: `RdpShadowManager`.
- `origin`: `https://github.com/neofart-art/microSOFT.git` — получение изменений, отправка коммитов, Pull Request и GitHub Actions.
- `fors`: `http://git.fors.technology/techadmin/MiniSoft.git` — внутренняя копия, которую пользователь обновляет со своего Windows-ПК.

Среда разработки не обращается к внутреннему серверу: не выполняет для него fetch, ls-remote, push, проверку HTTP или авторизации. Автоматическое зеркалирование/задания синхронизации не настроены. Все дальнейшие изменения отправляются в GitHub. Другие проекты, включая аудит сетевых папок, не меняются без отдельного задания. Рабочая ветка не объединяется с main автоматически.

## Локальные remotes

Перед изменением проверить `git remote -v` и `git status --short --branch`. В текущей сессии прежний `origin` (внутренний сервер) переименован в `fors`, а прежний `github` — в `origin`. Дубликаты не добавлялись. Ветка настроена на `origin/codex/rdp-shadow-manager`.

При настройке другого клона сначала проверить существующие имена и URL: не выполнять remote add вслепую и не заменять неизвестные remotes. Пароли/токены не включать в URL, команды или файлы проекта; использовать штатный credential manager или подключение среды.

История и существующая функциональность сохраняются. В текущей облачной сессии файлы приложения изначально не были полноценным Git-клоном; доступ к истории и отправка коммитов выполняются подключённым инструментом GitHub. Настройка локальных remotes не означает, что локально получены Git-объекты. До восстановления обычного Git-транспорта shell-каталог остаётся без локальной истории. Архивы исходных файлов и состояния перед возвращением GitHub сохранены в рабочем каталоге сессии `work/migration`; reset --hard, очистка и force push не использовались.

## Внутренняя копия — вручную с Windows-ПК пользователя

Следующие команды предназначены **только для Windows-ПК пользователя с доступом к обоим серверам**, не для облачной среды. Они не запускаются программой, скриптом сборки или workflow.

Проверить рабочую папку и remotes, сохранить незакоммиченные изменения, затем получить обе стороны:

```powershell
git status --short --branch
git remote -v
git fetch origin
git fetch fors
git switch codex/rdp-shadow-manager
git merge --ff-only origin/codex/rdp-shadow-manager
git log --oneline --left-right origin/codex/rdp-shadow-manager...fors/codex/rdp-shadow-manager
```

Если копия `fors/codex/rdp-shadow-manager` существует, проверить, что она является предком актуальной ветки GitHub:

```powershell
git merge-base --is-ancestor fors/codex/rdp-shadow-manager origin/codex/rdp-shadow-manager
# Продолжать только при коде завершения 0.
# Выполнять push только после успешного обновления локальной ветки и проверки её SHA.
git rev-parse HEAD
git rev-parse origin/codex/rdp-shadow-manager
git push fors codex/rdp-shadow-manager:codex/rdp-shadow-manager
git ls-remote fors refs/heads/codex/rdp-shadow-manager
```

Сверить SHA локальной ветки, origin и результата ls-remote. Перед push локальная ветка должна соответствовать проверенной версии GitHub. Если ветка внутренней копии ещё отсутствует, создать её обычным push только после проверки состояния сервера.

Если любая команда завершается ошибкой, локальная ветка имеет собственные коммиты или истории расходятся — остановиться, сохранить обе стороны и сначала разобрать различия. Не использовать force push, reset --hard, автоматическое удаление чужих коммитов или зеркальный push всего репозитория. Комментарии в примере не являются автоматическими проверками: код завершения и SHA проверяет пользователь. Разрешение конфликтов и согласование изменений выполнять в рабочей ветке; не объединять её с main без отдельного задания.

## Portable-сборка

Поддерживаемая автоматическая сборка: GitHub Actions, workflow `.github/workflows/rdp-shadow-manager.yml`, название **RDP Shadow Manager Windows x64**. Он запускается для изменений программы/своего workflow в рабочей ветке и PR, использует Windows runner и .NET 10 SDK, выполняет автоматические и smoke-проверки, публикует:

- `RdpShadowManager-win-x64` — portable ZIP;
- `RdpShadowManager-layout-checks` — снимки и результаты проверок разметки.

Скачать артефакты можно из успешного запуска Actions для нужного коммита после входа в GitHub. Срок хранения — 30 дней. Распаковать архив артефакта и вложенный `RdpShadowManager-win-x64.zip`, запустить `RdpShadowManager.exe`; установка .NET/Python на рабочем ПК не требуется.

Локальная сборка на Windows с .NET 10 SDK и Windows PowerShell 5.1:

```powershell
./RdpShadowManager/build-portable.ps1
```

Результат — `RdpShadowManager/artifacts/RdpShadowManager-win-x64.zip`. Скрипт не отправляет исходники или артефакты на внутренний сервер. Наличие CI/runner на внутреннем сервере для разработки не требуется и из облачной среды не проверяется.

Прежняя попытка сделать внутренний сервер основным остановилась на недоступном прокси среды до получения истории. Она отменена новым порядком работы: GitHub — основной источник разработки, внутренний сервер — ручная копия пользователя. Текущие результаты CI следует проверять по конкретному коммиту GitHub; реальные операции питания остаются допустимы для проверки только на выделенной тестовой машине.
